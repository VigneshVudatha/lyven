1. Project Overview

LYVEN is a dedicated Direct-to-Consumer (D2C) e-commerce web platform engineered for an independent Indian streetwear label. The brand specializes in heavyweight (240 GSM Combed French Terry Cotton) graphic-print oversized drop-shoulder T-shirts produced in limited-quantity collections.

1.2 Core Capabilities

  • High-Fashion Streetwear Aesthetic: Dark theme, brutalist typography, multi-angle vector mockups, and micro-animations.
  • Indian Checkout Engine: Strict regex validation for 10-digit Indian mobile numbers (^[6-9]\d{9}$), 6-digit postal PIN codes (^[1-9]\d{5}$), Indian states selection, and client idempotency UUID keys.
  • Dual Payment Support: Instant online checkout via Razorpay Standard (UPI, Cards, NetBanking, Wallets) and native Cash on Delivery (COD).
  • Customer Account & Order Tracking: Supabase Auth-powered session management (/account, /my-orders) and public self-service AWB order tracking (/track).
  • Secured Admin Backoffice: HMAC-SHA256 session-protected portal (/admin) for revenue KPIs, order dispatch updates (carrier name, AWB code), and live inventory matrix.
  • Bespoke Custom Design Studio: Interactive garment configurator (/custom-design) with fabric selection, artwork upload, and direct WhatsApp concierge handoff.
  • Statutory Indian GST Invoicing: Tax calculation modal computing 5% GST (Intra-state CGST + SGST 2.5% each; Inter-state IGST 5%) under HSN Code 6109.

3. Project Architecture & Data Flow

3.1 Application Architecture

The platform follows a layered architectural design enforcing strict boundaries between presentation, domain orchestration, and data persistence:

3.2 Dual-Mode Repository Pattern

A foundational architectural feature of LYVEN is the Repository Abstraction Layer implemented in lib/db/repository.ts. The application functions in two distinct operational modes without code modifications:

  • Cloud Persistence Mode (Supabase): When valid credentials (NEXT_PUBLIC_SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY) are present and the database is accessible, queries execute directly against PostgreSQL tables via the Supabase client.
  • Zero-Crash In-Memory Fallback Mode: If Supabase credentials are missing or network connectivity to the cloud is interrupted, the repository catches the error, serves the seed catalogue from lib/products/data.ts, and logs orders, payments, and enquiries into internal memory maps (inMemoryOrders, inMemoryPayments).

3.3 Order & Payment Lifecycle Flow

  1. Cart Assembly: The customer adds items to their persistent cart, selecting specific size variants (S through XXL).
  2. Checkout Initiation: The customer submits shipping details via POST /api/orders/create with an idempotency UUID key.
  3. Server Price Enforcement: The backend completely discards any client-supplied prices, recalculating line items and totals against authoritative server pricing (₹400 / ₹388).
  4. Payment Branching:
    • Razorpay: An official Razorpay Order is created via the SDK (amount in paise). The client triggers the checkout.js modal. Upon completion, the client posts credentials to POST /api/payments/verify. The server computes the HMAC-SHA256 signature using RAZORPAY_KEY_SECRET and crypto.timingSafeEqual. Once verified, variant stock is decremented via the deduct_variant_stock stored procedure, and order status transitions to CONFIRMED.
    • Cash on Delivery (COD): Stock is decremented immediately, order status is initialized to CONFIRMED, and payment status is recorded as PENDING.
  5. Fulfillment & Notification: An asynchronous HTTP request notifies the admin inbox (lyven.support1@gmail.com) and dispatches a customer order confirmation email.

5. Database Structure (Supabase PostgreSQL)

Architectural Note: Supabase PostgreSQL vs Firebase
While legacy documentation files mention Firebase, the codebase has been fully migrated to Supabase PostgreSQL. There are zero Firebase packages in package.json. All database operations target PostgreSQL relational tables.

5.1 PostgreSQL Relational Schema (9 Tables)

Table Name Primary Key Foreign Keys & Relationships Key Columns & Data Types
products id (text) None name, slug (UK), price (numeric), fabric, gsm, is_active, tags (jsonb)
product_images id (text) product_id → products(id) url, alt_text, sort_order (int), is_primary (bool)
product_variants id (text) product_id → products(id) size, sku (UK), stock_quantity (int), price_override
inventory_movements id (text) variant_id → product_variants(id) quantity_change (int), reason, reference_id, created_at
orders id (text) user_id → auth.users(id) order_number (UK), customer_phone, shipping_address (jsonb), total_amount, status, payment_status, tracking_number
order_items id (text) order_id, product_id, variant_id size, quantity (int), unit_price, total_price
payments id (text) order_id → orders(id) razorpay_order_id, razorpay_payment_id, razorpay_signature, amount, status
order_status_history id (text) order_id → orders(id) status, note, created_at
custom_design_enquiries id (text) None customer_name, customer_phone, garment_type, print_placements (jsonb), artwork_url

5.2 Stored Procedures & Atomic Functions

  • deduct_variant_stock(variant_id text, qty int): Atomically verifies sufficient inventory, decrements stock_quantity, and logs a record to inventory_movements. Prevents overselling during drops.
  • restore_variant_stock(variant_id text, qty int): Atomically restores stock upon order cancellation or payment failure.

5.3 Storage Buckets & Row Level Security (RLS)

  • Storage Buckets: lyven-products (public, product media) and custom-designs (private, user artwork uploads).
  • Row Level Security (RLS): Enabled across all 9 tables. Public reads are granted for active products and variants. Customers can only read orders where auth.uid() = orders.user_id. All write mutations to stock and order statuses are restricted to service_role.

10. Deployment & Known Architectural Notes

10.1 Deployment Configuration

  • Vercel Serverless Ready: The application compiles cleanly with npm run build into standalone serverless Lambda functions.
  • Dynamic Metadata Base: Configured in app/layout.tsx to resolve process.env.NEXT_PUBLIC_BASE_URL with a fallback to avoid OpenGraph URL build warnings.
  • Repository Remote: Linked to GitHub repository https://github.com/VigneshVudatha/lyven.git on branch main.

10.2 Architectural Observations & Recommendations

  • Documentation Realignment: Legacy references to Firebase/Firestore in README.md should be updated to point to the Supabase setup guides.
  • API Route Consolidation: The checkout flow exclusively utilizes /api/orders/create and /api/payments/verify. The alternative direct routes (/api/create-order and /api/verify-payment) should be maintained as aliases or deprecated.
  • Production Admin Secrets: Ensure ADMIN_PASSWORD and ADMIN_SECRET are populated with strong random strings in the production host settings.
